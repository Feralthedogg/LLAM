New in {{ config.extra.llam_version }}: managed C

llam_runtime_create() runs task code from the LLVM 23.1.2 managed producer on qualified native profiles and preempts its CPU loops without application polls.

Read the managed C guide See native profiles

Built to be verified

Verification is platform-local. A green Linux run does not prove the kqueue or Windows IOCP backend, so each one runs its own gates.

Platform gates

Every backend verifies on its own operating system, against its own kernel contract.

make verify-linux CC=gcc

Stress and soak

Long runs exercise core runtime behavior without depending on the example chat server.

make test-runtime-soak

Hardening

Static analysis, dependency audit, and heavy fuzzing before release candidates and security-sensitive changes.

make test-hardening

Sanitizers

ASan and TSan builds keep their objects separate from ordinary builds.

make test-asan

ABI contract

Struct handshakes, compatible prefixes, and shared-library exports stay under test within an ABI major.

make audit-shared-exports

Managed compiler and SDK

A pinned LLVM 23.1.2 job must execute all four stages. A missing or skipped stage is a failure.

scripts/verify_managed_ci.py

One API. Three native backends.

The same llam_read() parks on the native backend for each platform. Unsupported descriptors fall back to a blocking helper, so a scheduler worker is not pinned.
